# 执行规则（Codex 与人工共同遵守）

编程由 Codex 执行（用户把提示词粘贴给 Codex），审查与教学由 Claude（本会话）负责。一次只推进一个研究单元。

1. **归属明确**：每次先说明正在执行的单元与任务组；任何分析、参数调整、实验都必须归属研究单元，不在台账之外临时改变策略。
2. **判据先行**：`decision-rule.md` 冻结（记录输入哈希/参数版本）后才允许实现与求解；冻结后不得修改阈值、场景、候选、参数或主要方向。
3. **证据三元组**：任何数值结论必须有 脚本 + 参数 + 代码/依赖版本，并附 run_id、输入 SHA-256 与运行环境（`run_manifest.json`）。文档结构通过 ≠ 模型通过。
4. **结果四分类**：`supported / refuted / inconclusive / invalid`；尚未执行一律 `verdict: null`。否定与不确定结果完整保留，不许删除失败记录。
5. **禁止凑数**：不得为匹配申报书数字（84.63%、87.08%、308680 元等）调整数据、参数或口径；结果由数据与模型自然产生。
6. **求解失败即停**：优化求解器状态非 Optimal（或数值异常）必须停止并报告，不得继续生成图表或结论。
7. **文件保护**：`444.docx` 与提示词原文只读；禁止批量删除文件或目录，删除须逐文件明确路径并由用户确认。
8. **数据诚实**：构造数据必须标明"构造算例，非真实电网数据"；真实数据必须记录来源、坐标、时间范围与转换方法。
9. **完成即停**：每个单元完成后停止，等待用户下一步指令；不得自动进入下一单元。
10. **修订走流程**：意外发现写入 `specs/roadmap.md` 的 Backlog；需要改变已执行单元的判据时新建单元并在旧 `findings.md` 记录原因。
