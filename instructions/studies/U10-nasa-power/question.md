# U10 单元问题

## 可判定的研究目标

在不运行调度或优化模型的前提下，验证一条冻结的 NASA POWER 数据管线能否把武汉的逐小时气象观测转换为项目可读、可审计的 **168 小时**风光荷输入。成功只表示该输入契约成立；它不表示真实气象下的经济性、可靠性或储能容量结论成立。

## 冻结的输入与输出

| 项目 | 冻结内容 |
|---|---|
| 地点 | 中国湖北省武汉市，纬度 `30.5900`、经度 `114.3000`（WGS84）；当地时区 `Asia/Shanghai`，UTC+08:00、无夏令时 |
| 数据端点 | `https://power.larc.nasa.gov/api/temporal/hourly/point` |
| 查询参数 | `parameters=ALLSKY_SFC_SW_DWN,WS50M&community=RE&longitude=114.3000&latitude=30.5900&start=20200101&end=20200107&format=JSON&time-standard=UTC` |
| 原始窗口 | 从 `2020-01-01T00:00:00Z`（含）至 `2020-01-07T23:00:00Z`（含），按 UTC 一小时一个区间，共 168 个时间戳；`end` 是 API 的包含日 |
| 本地显示 | 同一窗口为 `2020-01-01T08:00:00+08:00`（含）至 `2020-01-08T07:00:00+08:00`（含），仅用于审计显示，不改变取样窗口 |
| 管线输出 | `data/processed/input_168h.csv`，列为 `hour,load,wind,solar`，恰好 168 行，`hour=0…167` |

负荷不是 NASA 数据：它是当前 24 小时构造负荷形状按 7 天循环、每天依次乘 `0.95, 1.00, 1.05, 0.95, 1.00, 1.05, 0.95` 得到的构造负荷，必须始终标记为“构造负荷，非真实负荷”。

## 上游证据与边界

- 上游接口契约：`src/data_loader.py`；其最低要求是四列均存在、数值有限且非负、`hour` 相邻差严格为 1、长度为 168。
- 上游数据规格：`instructions/specs/data.md`，其中风、光均为可用出力（MW）。
- 本单元只设计和未来验证数据获取、留档、转换和质量控制；本次不下载数据、不安装依赖、不运行实验。

若原始响应不可追溯、时间窗不是上述 168 个 UTC 小时、关键变量无法解释为规定单位，或未按冻结规则处理缺失值/重复时间戳，运行不能产生有效的下游输入，判定规则见 `decision-rule.md`。
