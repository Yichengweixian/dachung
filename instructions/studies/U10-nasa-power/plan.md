# U10 执行计划

本文件是未来获准执行时的顺序清单；当前只补充文档，不执行其中任何下载、安装或实验。

1. 冻结核对：计算并记录 `question.md`、`design.md`、`decision-rule.md` 的 SHA-256；逐字核对端点、参数、武汉 WGS84 坐标、UTC 窗口、时区、变量、转换常数和阈值。验收：三份哈希及运行 ID 写入 manifest 草稿。失败：停止，建立新单元而不修改冻结规则。
2. 获取与原始留档：仅调用冻结 URL，按 `design.md` 的三个 raw 文件名落盘并复算哈希。验收：HTTP 200、响应 JSON、请求元数据、字节哈希齐全。失败：网络、DNS、超时、429 或 5xx 记录为 `inconclusive`；4xx、参数回显不符或留档缺失记录为 `invalid`；均不生成输入。
3. 解析与质量门：读取 API 元数据单位，提取 `ALLSKY_SFC_SW_DWN`、`WS50M` 和 UTC 键，构造期望的 168 键集合。验收：键集合完全相同，所有缺失/重复/非有限/范围违规计数为 0。失败：保留报告和原始响应，停止；不得插补、删重、裁剪或更换日期。
4. 转换与输出：只使用设计中的风机曲线、光伏公式和构造负荷规则，写入带运行 ID 的副本，再原子性更新 `data/processed/input_168h.csv`。验收：列名、168 行、`hour=0…167`、范围和零辐照度光伏规则均通过。失败：不更新规范文件，标记为 `refuted` 或 `invalid`（按判定规则）。
5. 契约与复现：调用 `validate_input_data(..., 168, 1.0)`；在同一原始文件、同一参数和同一脚本版本下再转换一次并比较输出 SHA-256。验收：两项均通过。失败：校验失败按根因停止；重跑哈希不一致为 `invalid`。
6. 证据登记：填充 `findings.md` 的运行 ID、每项门槛、原始/输出哈希、质量报告、manifest 和单一 verdict。验收：不含虚构产物或结果，verdict 符合 `decision-rule.md`。失败：保持 `verdict: null`，不要补造证据。

本单元不修改 `STATUS.md`、`specs/roadmap.md` 或任何 Git 状态，也不运行优化、调度、绘图或稳健性敏感性实验。
